EL QUIET REBUILD — WEBSITE OVERVIEW

1. WHAT IS EL QUIET REBUILD?

EL Quiet Rebuild is a space for women who want to learn, think, grow and become the women they are capable of becoming.

EL is not only about consuming information or feeling motivated. Women are encouraged to learn with useful resources,
think about what they have learned, rebuild the areas of their lives that need attention, apply that knowledge in real life,
and gradually become the women they are working toward.

2. THE EL QUIET REBUILD FRAMEWORK

Learn → Think → Rebuild → Apply → Become

LEARN
Gain useful knowledge through books, resources, discussions and practical guidance.
Learning gives a woman information and perspectives she may not have had before.

THINK
Do not accept information automatically. Question what you learn, consider what it means for your own life, 
examine different perspectives, and form your own understanding.

REBUILD
Notice what is not right, working, or aligned in your life, and begin making intentional changes to build the life and the woman you want to become.

APPLY
Put what you have learned, considered and decided into practice. Turn knowledge and intention into actions, habits,
decisions and standards that shape everyday life.

BECOME
Grow into the woman you are intentionally building through what you learn, how you think, what you rebuild, and what you consistently apply. 
Becoming is an ongoing process, not a finished destination.

3. EL PHILOSOPHY AND SIGNATURE

CORE PHILOSOPHY
Less display. More depth.

MEANING
EL Quiet Rebuild values substance over performance. Growth does not need to be constantly displayed to be real. 
The deeper work happens in what a woman learns, how she thinks, the standards she develops, the decisions she makes, and how she lives.

This philosophy should influence EL's content, products, website and creative decisions. 
EL should not add something simply because it is trendy, impressive or visually attractive. It should have a meaningful purpose and contribute to depth.

SIGNATURE
Become before the world notices. I’ll meet you there.

MEANING
“Become before the world notices” is an invitation to do the work of becoming before there is recognition, applause or external validation. 
A woman does not need the world to notice her progress for that progress to matter.

“I’ll meet you there” represents EL’s relationship with her. EL is not speaking down to her from a finished destination. 
It is a space that accompanies, guides and supports her as she learns, thinks, rebuilds, applies and becomes.

Together, the signature reflects quiet transformation: becoming through depth, intention and 
consistent action before the results are visible to everyone else.

4. PURPOSE OF THE WEBSITE

EL Quiet Rebuild should not exist only to look beautiful. Its purpose is to give women something meaningful to take away from their time here.

A woman should be able to learn something, think about what it means for her own life, feel motivated to make meaningful changes, and take action. 
The website should encourage movement from inspiration into intentional action.

5. WHO THE WEBSITE IS FOR

EL Quiet Rebuild is for a woman who wants to build and become more intentional about her life. She wants to develop herself across areas such as 
her finances, confidence, personal growth, self-awareness, knowledge, standards, skills and the way she presents herself.

EL recognizes that becoming is not limited to one area of life. Inner development and outward choices can become more aligned as a woman grows, 
but appearance does not determine her worth. The deeper goal is to help her become more intentional about who she is, how she lives and who she is becoming.

6. WEBSITE STRUCTURE

HTML — THE STRUCTURE
HTML (HyperText Markup Language) provides the structure and content of the website. It tells the browser what exists on a page, 
such as headings, paragraphs, images, links, buttons, navigation and sections.

A simple way to remember it:
HTML = the structure or foundation of the webpage.

CSS — THE PRESENTATION AND DESIGN

CSS (Cascading Style Sheets) controls how the website looks and is presented. It controls things such as colours, fonts, spacing, sizes, borders, 
positioning and layout.

CSS is also responsible for helping the website adapt visually to different screen sizes, such as laptops and mobile phones.

A simple way to remember it:
CSS = the beautification and visual presentation of the website.

JAVASCRIPT — THE BEHAVIOUR AND INTERACTION

JavaScript controls much of the interactive behaviour of a website. It can make the website respond when a visitor performs an action, such as clicking a
button, opening a menu, submitting information or interacting with a feature.

A simple way to remember it:
JavaScript = the electricity and mechanisms that help make the website respond and feel alive.

INDEX.HTML — THE HOMEPAGE

index.html is the main homepage file for EL Quiet Rebuild. It contains the HTML structure and content of the homepage.

A simple way to remember it:
index.html = the front door of the website.

STYLE.CSS — THE WEBSITE DESIGN

style.css contains the CSS rules used to control the visual presentation of EL Quiet Rebuild. It includes things such as colours, fonts, spacing, buttons, 
borders, layouts and how pages adapt to different screen sizes.

Changes made in style.css can affect multiple parts or pages of the website, so changes should be made carefully and tested before being published.

A simple way to remember it:
style.css = EL Quiet Rebuild's visual design instructions.

SCRIPT.JS — WEBSITE BEHAVIOUR

script.js is the JavaScript file used for interactive behaviour on EL Quiet Rebuild. It can contain instructions that tell the website how to respond when 
certain actions happen.

Not every part of the website needs JavaScript. Normal content and links can still work through HTML without JavaScript.

A simple way to remember it:
script.js = instructions for website behaviour and interaction.

FOLDERS — ORGANIZING THE WEBSITE

Folders help keep related website files and pages together. As EL Quiet Rebuild grows, organizing pages into folders prevents the project from becoming 
cluttered and difficult to manage.

For example, the reading-room folder contains pages and content that belong to the Reading Room.

A simple way to remember it:
Folders = keeping related parts of the website organized and easier to manage.

HOW PAGES CONNECT

Links can give the browser directions to another webpage file.

For example:

reading-room/reflection-room.html

means:
Go into the reading-room folder and open the reflection-room.html webpage.

A simple way to remember it:
A file path = directions to where a file lives.

7. GIT & GITHUB WORKFLOW

Git helps track and save versions of the EL Quiet Rebuild website project.

GitHub is the online home where the Git project and its saved versions are stored.

GIT STATUS

Command:
git status

Purpose:
Checks the current state of the project and shows what has changed.

A simple way to remember it:
git status = What changed?

GIT ADD

Command:
git add

Purpose:
Prepares the change you want to include in the next saved version.

A simple way to remember it:
git add = Prepare the change.

GIT COMMIT

Command:
git commit

Purpose:
Creates a saved version of the changes you prepared.

A commit message describes what was changed in that version.

A simple way to remember it:
git commit = Save this version.

GIT PUSH

Command:
git push

Purpose:
Sends the saved Git version from your computer to GitHub, updating the project stored there.

A simple way to remember it:
git push = Update GitHub.

8. PUBLISHING THE WEBSITE

LOCAL WEBSITE FILES

The EL Quiet Rebuild website files on my computer are where I build and edit the website.

When I make a change and press Ctrl + S, the change is saved on my computer. This does not automatically update the public website.

A simple way to remember it:
Local website files = where I build and edit EL.

GITHUB

GitHub stores the EL Quiet Rebuild project online.

After I make and save changes on my computer, I use Git to prepare and save a version of those changes. When I use git push, that saved version is sent to 
GitHub.

A simple way to remember it:
GitHub = the online home of my website project.

GITHUB PAGES

GitHub Pages takes the website files stored in the GitHub project and publishes them as the public EL Quiet Rebuild website.

After I push a new saved version to GitHub, GitHub Pages can deploy that version so the changes appear on the live website.

A simple way to remember it:
GitHub Pages = publishes my website for people to see online.

THE PUBLISHING JOURNEY

1. I edit the website files on my computer.
2. I press Ctrl + S to save my changes on my computer.
3. I use Git to check, prepare and save the changes.
4. I use git push to send the saved version to GitHub.
5. GitHub Pages publishes the updated website.
6. I check the live website to make sure the change works correctly.

A simple way to remember it:

Computer → Git → GitHub → GitHub Pages → Live Website

9. THE QUIET REBUILD CHECK-IN SYSTEM

PURPOSE

The Quiet Rebuild Check-In is a free EL resource designed to help a woman notice which areas of her life may need attention. It also gives her a way to join the EL Quiet Rebuild email list and continue her journey with EL.

HOW THE SYSTEM WORKS

1. A visitor arrives at the EL Quiet Rebuild Check-In page.
2. She clicks “Get the Free Check-In.”
3. She is directed to the MailerLite sign-up form.
4. She enters her name and email address.
5. MailerLite adds her as a subscriber.
6. The MailerLite automation sends the Check-In delivery email.
7. She clicks “Open Your Quiet Rebuild Check-In” in the email.
8. The Quiet Rebuild Check-In PDF opens.

Simple journey:

EL Website → Check-In Page → MailerLite Form → Email List → Delivery Email → Check-In PDF

IF SOMETHING GOES WRONG

Because the Check-In system has several connected parts, first identify where the journey stops before making changes.

If the “Get the Free Check-In” button does not open the sign-up form:
Check the website link to the MailerLite form.

If the form opens but cannot be submitted:
Check the MailerLite form.

If the form works but the delivery email does not arrive:
Check the MailerLite automation and delivery email.

If the email arrives but the Check-In does not open:
Check the PDF link inside the delivery email.

Important:
Do not change several parts of the system at once. First identify which step is failing, then investigate that part.

11. BRAND & WEBSITE RULES

CORE DESIGN PRINCIPLE

Less display. More depth.

EL Quiet Rebuild should prioritize substance, clarity and purpose over unnecessary display.

Website elements should not be added simply because they are trendy, impressive, animated or visually attractive. Each element should have a reason 
for being there and should support the visitor's experience or EL's purpose.

A simple decision question:
What purpose does this serve?

If an element adds visual noise without adding meaning, usefulness or a better experience, it may not belong on EL.

VISUAL DIRECTION

EL Quiet Rebuild should feel calm, thoughtful, warm, editorial and intentional.

The main visual direction uses:
- Dark espresso
- Cream / ivory
- Terracotta
- Gold and olive as supporting tones

The design should give content room to breathe through thoughtful spacing and clear hierarchy.

Avoid making every piece of content look like a card or placing everything inside boxes. Containers, borders and cards should be used when they help 
organize or distinguish content.

A simple rule to remember:
A box should have a reason to be a box.

The goal is not to make EL look busy or impressive. The design should support the ideas, reading experience and purpose of the website.

EL SIGNATURE

Become before the world notices. I’ll meet you there.

This is an important EL Quiet Rebuild signature and should not be shortened, rewritten or replaced casually.

“Become before the world notices” represents doing the work of becoming before recognition, applause or external validation.

“I’ll meet you there” represents EL’s relationship with the woman: EL accompanies, guides and supports her rather than speaking to her from a position of 
superiority.

When the signature is used, preserve the complete meaning and wording:

Become before the world notices. I’ll meet you there.

15. MAKING A WEBSITE UPDATE

BASIC UPDATE PROCESS

When making a change to EL Quiet Rebuild, make the change carefully and test it before publishing it to the live website.

1. Open the EL Quiet Rebuild project in VS Code.
2. Find and open the file that contains what I want to change.
3. Make the change.
4. Press Ctrl + S to save the change on my computer.
5. Test the change locally and make sure it works and looks as expected.

Important:
Saving a file does not publish the change to the live website.

A simple rule to remember:
Change → Save → Test

PUBLISHING THE UPDATE

After the change has been saved and tested:

1. Use git status to check what has changed.
2. Use git add to prepare the changes that should be included.
3. Use git commit with a clear message to save a new version.
4. Use git push to send the saved version to GitHub.
5. Check that GitHub Pages successfully deploys the new version.
6. Open the live EL Quiet Rebuild website and verify that the update appears and works correctly.

A simple way to remember it:

Change → Save → Test → Status → Add → Commit → Push → Deploy → Verify

16. BASIC TROUBLESHOOTING

MAIN PRINCIPLE

Do not start changing several things when something goes wrong.

First ask:
Where does the problem begin?

CHANGE DOES NOT APPEAR ON THE LIVE WEBSITE

Check:
1. Did I save the file with Ctrl + S?
2. Did I test the correct change locally?
3. Did I complete the Git process and push the new version to GitHub?
4. Did GitHub Pages deploy successfully?
5. Am I checking the correct live page?

LINK DOES NOT WORK

Check:
1. Is the link pointing to the correct file or webpage?
2. Is the file path correct?
3. Does the destination file actually exist?

DESIGN LOOKS WRONG

Check:
1. Did I change the correct HTML or CSS?
2. Could a CSS change be affecting more than one element or page?
3. Does the problem happen on both laptop and mobile?

DEPLOYMENT FAILS

Do not immediately change the website code.

First check the GitHub Pages deployment information to understand what failed.

IMPORTANT RULE

Diagnose first → identify the failing part → change one thing → test again.
